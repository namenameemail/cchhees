# Контракт событий, ходов, условий и действий

> Источник правды для типов условий, субъектов и операндов. При изменении контракта сначала правим этот файл, затем код (`conditionContexts.ts`, `events.ts`, `evaluate.ts`, `geometry.ts`, `migrateEventRules.ts`, `displaceFigure.ts`, UI).

## Глоссарий

### Субъекты

| Сокращение | id | Описание |
|------------|-----|----------|
| сф | `$moved` | Сдвинутая фигура (ходящая); координата = `from` хода |
| нф | `$steppedOn` | Фигура, на которую наступили |
| перепрыг | `$hoppedOver` | Перепрыгнутая фигура |
| ф | фильтр | Фигура под фильтром Ф2 (конкретный тип/состояние или `*`) |
| рядом | `subject.nearby` | Только действия: boolean + `cells[]`; цели = фигуры в областях вокруг якорей из `entries` |

### Операнды

| Сокращение | Описание |
|------------|----------|
| О | Область доски (прямоугольник x1,y1,x2,y2) |
| О Ф2 | Область фигуры (смещения относительно якоря + опционально фильтр якоря) |
| XY | Клетка доски |
| XY[] | Список клеток |
| DX,DY | Смещение хода |
| Ф2 | Фильтр одной фигуры |
| Ф2[] | Список фильтров (режим any/all) |
| С | Индекс состояния |

### Контекст условий

| Значение | Описание |
|----------|----------|
| `event` | Только правила событий фигур |
| `move` | Только условия вариантов хода (`FigureMoveVariant.conditions`) |
| `both` | Оба контекста |

### Момент вычисления (`movePhase`)

Применим только к `inBoardArea`, `inFigureArea`, `hasFigureInArea`. Поле `movePhase?: 'before' | 'after' | 'entered' | 'left'`, default `after`.

| Значение | Семантика |
|----------|-----------|
| `before` | состояние ДО хода (сф → `from`; прочие субъекты → снэпшот доски до хода, если доступен) |
| `after` | состояние ПОСЛЕ хода / текущее (сф → `to`; прочие субъекты → текущая доска) |
| `entered` | true(after) И false(before) — «только что оказалась внутри» |
| `left` | false(after) И true(before) — «только что покинула» |

Вычисляется движком до выполнения действий события (снапшот "до" фиксируется на старте обработки хода). Ограничение: внутри правил `steppedOnBy` снэпшот доски "до" не прокидывается движком (`evaluateSteppedOnRule`), поэтому там `before`/`entered`/`left` фактически деградируют до `after`.

Для сценария «фигуру сместили» используйте не условие, а событие `onMove` с `params.cause: 'displacement'` (или `'any'`) — оно надёжно срабатывает при **каждом** смещении фигуры действием `displaceFigure`, независимо от того, приземлилась ли она на пустую клетку или на занятую (в занятом случае цепочка продолжается через `steppedOnBy`-правило занимавшей клетку фигуры). Внутри такого срабатывания `$moved` — это именно смещённая фигура (с корректными `from`/`to` этого конкретного смещения, не корневого ручного хода), `$steppedOn` — фигура, на которую она попала, если приземлилась на занятую клетку (иначе роль просто не резолвит инстансов). `movedBy` и геометрия `before`/`entered`/`left` для `$moved` в этом случае корректно отражают дельту/позиции именно этого смещения.

## События

Формат: `<id> | <подпись> | <контекстные поля>`

| id | Подпись | Контекстные поля |
|----|---------|------------------|
| `onMove` | ход фигуры | `cause(manual\|displacement)`, `movedFigure`, `from`, `to`, `eatedFigures[]?`, `hoppedFigures[]?` |
| `steppedOnBy` | на фигуру наступили | `cause`, `stackPosition`, `stackIndex`, stepped-on target |
| `leaveBoard` | выход с доски | — |

`onMove` с `cause: 'displacement'` срабатывает для **каждой** фигуры, смещённой действием `displaceFigure` (в т.ч. рекурсивно — смещение может само попасть в зону другого/того же правила и вызвать следующее смещение). Это единственный обработчик для сценария «фигуру сместили» — отдельного типа события для этого не заведено.

## Условия

Формат: `<id> | <подпись> | <контекст> | <субъект> | <операнды> | <момент>`

| id | Подпись | Контекст | Субъект | Операнды | Момент |
|----|---------|----------|---------|----------|--------|
| `inBoardArea` | находится в области доски | both | сф, нф, ф | О | `movePhase` (before/after/entered/left) |
| `inFigureArea` | находится в области фигуры | both | сф, нф, ф | О Ф2 | `movePhase` (before/after/entered/left) |
| `hasFigureInArea` | имеет фигуру в области | both | сф, нф, ф | О (относительно субъекта) + Ф2[] (любой/все) | `movePhase` (before/after/entered/left) |
| `movedBy` | сдвинулась на | both | сф | DX,DY | — |
| `isFigure` | является | both | сф, нф, ф | Ф2[] | — |
| `isNotFigure` | не является | both | сф, нф, ф | Ф2[] | — |
| `hoppedOverFigures` | перепрыгнула фигуры | both | сф | Ф2[] (любой/все) | — |
| `exitedBoard` | вышла за границу доски | both | сф | — | — |

Условия `landedOnCell`, `leftCell`, `landedInBoardArea`, `landedInFigureArea`, `figureEnteredArea`, `landedOnFigure`, `steppedOnByFigure`, `onCells`, `aboveFigures`, `belowFigures` удалены как отдельные типы — их сценарии покрываются `inBoardArea`/`inFigureArea`/`hasFigureInArea` с нужным `movePhase` (стековые `aboveFigures`/`belowFigures` убраны без замены). См. [Миграция удалённых типов](#миграция-удалённых-типов).

#### `orientToTeamDirection` (галочка в UI)

Поле `orientToTeamDirection?: boolean` в params условий/действий с координатами и в `subject.nearby`.

- **false / отсутствует** — абсолютные координаты доски (XY 1-based) или смещения по оси доски (dx/dy, cells как offset в координатах доски).
- **true** — канонические смещения (вперёд = `{ x: 0, y: 1 }`), повёрнутые по `moveDirection` команды **якоря ориентации**, затем применённые как offset от позиции субъекта/якоря.

Якорь ориентации: figureId субъекта условия, якорной фигуры области, ходящей фигуры (`movedBy`), целевого субъекта действия; fallback — `ownerFigureId` правила.

**Исключение — `inBoardArea`**: `x1,y1,x2,y2` там не смещение, а абсолютная область доски (операнд О), поэтому `orientToTeamDirection: true` не привязывает область к позиции фигуры — вместо этого сама область поворачивается в координатах доски (n×m) под `moveDirection` команды субъекта, независимо от текущей/предыдущей позиции фигуры:

| `moveDirection` | `(x, y)` → абсолютные координаты доски |
|---|---|
| `up` (как при выключенной галочке) | `(x, y)` |
| `down` | `(n+1-x, m+1-y)` |
| `left` | `(y, m+1-x)` |
| `right` | `(n+1-y, x)` |

где `n`/`m` — размеры доски (`BoardParameters`).

Миграция: для `hasFigureInArea` без поля в сохранённых данных default `true` (совместимость с move-вариантами).

#### Семантика subject

- Поле `subject` фильтрует **экземпляры**, к которым относится условие (роли сф/нф/перепрыг или конкретный фильтр Ф2).
- **`movedBy`**, **`hoppedOverFigures`**: subject применяется к **ходящей** фигуре (`actorPlacement`); сдвиг или список перепрыгнутых проверяются только если hopper/mover входит в subject.
- **`exitedBoard`**: subject в runtime пока не проверяется (placeholder для правил `leaveBoard`).

#### Семантика `hasFigureInArea`

- Область (`cells`) — смещения относительно позиции субъекта, взятой в фазе `movePhase` (для сф — честно `from`/`to` в зависимости от фазы; ранее было расхождение — субъект сф всегда неявно брал позицию до хода независимо от намерения, теперь это явно управляется `movePhase`).
- При `orientToTeamDirection: true` — каноническая система + поворот по команде субъекта (см. выше).
- На каждой клетке области (в выбранной фазе) проверяется **весь стек**; субъект (свой `instanceId`) не учитывается.
- `matchMode: any` — хотя бы одна фигура в области подходит под фильтр.
- `matchMode: all` — каждый entry фильтра Ф2[] должен быть представлен среди фигур в области.
- Субъект может быть нф (`$steppedOn`) — например, чтобы проверить «есть ли в моей клетке после хода фигура заданного типа» (частично покрывает бывший сценарий `steppedOnByFigure`, см. миграцию ниже).

#### Миграция удалённых типов

| Старый тип | Новый эквивалент |
|---|---|
| `landedOnCell(x,y)` | `inBoardArea{x1:x,y1:y,x2:x,y2:y, movePhase:'after'}` |
| `leftCell(x,y)` | `inBoardArea{x1:x,y1:y,x2:x,y2:y, movePhase:'left'}` |
| `landedInBoardArea` | `inBoardArea{..., movePhase:'after'}` |
| `landedInFigureArea` / `figureEnteredArea` | `inFigureArea{..., movePhase:'entered'}` |
| `landedOnFigure{figures,matchMode,stackTarget,stackIndex}` | `hasFigureInArea{cells:[{0,0}], figures, matchMode, movePhase:'after'}` (теряет `stackTarget`/`stackIndex`) |
| `steppedOnByFigure{stepperFigures,matchMode}` (subject нф) | `hasFigureInArea{cells:[{0,0}], figures:stepperFigures, matchMode, movePhase:'after'}`, subject остаётся нф |
| `onCells{cells[]}`, 1 клетка | `inBoardArea` (вырожденный прямоугольник) |
| `onCells{cells[]}`, ≥2 клеток | нет эквивалента — условие отбрасывается при загрузке старого проекта (см. debug-log) |
| `aboveFigures` / `belowFigures` | нет эквивалента — условие отбрасывается при загрузке старого проекта (см. debug-log) |

Миграция выполняется автоматически при загрузке старых сохранённых правил (`migrateEventRules.ts`, `normalizeMoveVariant`).

## Действия

Субъект действия — поле `subject` (по умолчанию: владелец правила для `onMove`, `$steppedOn` для `steppedOnBy`).

Поля `subject`:

- `entries` — якоря (сф, нф, перепрыг, ф)
- `matchMode` — `any` / `all` для якорей
- `nearby` — `{ enabled, cells, orientToTeamDirection? }` (опционально): при `enabled` действие применяется ко **всем фигурам в стеках** клеток области вокруг каждого якоря

| id | Подпись | Субъект | Операнды |
|----|---------|---------|----------|
| `setSelfState` | сменить состояние субъекта | subject (по умолч. владелец) | С |
| `setOtherState` | сменить состояние субъекта | subject | С |
| `displaceFigure` | переместить субъекта на | subject (по умолч. владелец) | DX,DY |
| `moveToCell` | переместить на | subject | XY |
| `moveToTray` | убрать субъекта в трей | subject (по умолч. владелец) | — |
| `spawnFigure` | создать фигуру | — | Ф2, XY, С |
